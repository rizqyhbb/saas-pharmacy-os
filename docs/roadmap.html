Overview

Seven milestones. M0–M3 deliver MVP v1 (the lean core, piloted with one design-partner apotek). M4–M5 deliver v1.1 (prescription, dispensing, compounding). M6+ is Phase 2 and Phase 3.

Estimates, not commitments. Effort is shown in relative sizes (S/M/L/XL) and agent-assisted working weeks. These are guesses made before any code exists and before a design partner is confirmed. Re-estimate after M0. No calendar dates are promised.

MVP v1

M1 · Counter

Size XL · ~3–4 weeks (guess)

A cashier can sell OTC fast, take payment, print a receipt, run a shift, and keep working when the internet drops.

Build

  • Search / scan with offline index (<150 ms p95, 20k SKUs)
  • Cart, unit select, discounts (permissioned), park/resume
  • Payments: cash, QRIS (manual confirm), transfer, card, split
  • Atomic sale commit + idempotency
  • Thermal receipt + share
  • Void vs refund (distinct)
  • Shift open / close, cash in/out, blind close
  • Offline outbox, sync worker, per-transaction sync state
  • Rx-required / controlled block at OTC counter

POS-1…12 · SHF-1…5 · SYN-1…6 · PRD-8

Stories

US-POS-1…10 · US-SHF-1…4 · US-SYN-1…4 · US-CAT-6

UI approach

  • All admin/POS screens via the impeccable skill
  • Counter is desktop/tablet-first; verify at ~390 px too
  • Write DESIGN.md before inventing tokens
  • D5 tax, D6 QRIS decided

Gate G1 — kill checkpoint: does offline work on real hardware?

  • ★ Duplicate submit creates exactly one sale
  • ★ 8-hour offline soak: 0 lost, 0 duplicated sales
  • ★ Two workstations sell the last unit offline → flagged conflict, never a silent drop
  • ≤ 4 interactions for a single-item sale; <100 ms add-to-cart on target device
  • Receipt prints on two common 58/80 mm printers

M4 · Prescription core

Size XL · ~4–5 weeks (guess)

A prescription goes from intake to hand-over with an attributable pharmacist decision and an immutable dispense record. Do not start without an APJ available for review.

Build

  • Person → Customer / Patient split; access-logged patient records
  • Prescriber records
  • Prescription intake (original text kept verbatim, mapped separately)
  • Screening checklist: administrative / pharmaceutical / clinical
  • Approve / Hold / Contact-prescriber (pharmacist-only, server-enforced)
  • Prescription state machine + status history
  • Reservation, FEFO pick list, final check
  • Rx checkout (cashier only when READY), partial fill
  • Etiket printing; archive + search; medication history
  • Duplicate / repeat / copy detection

Go / no-go checkpoints

Questions that decide whether to continue, narrow, or stop. Full criteria in SUCCESS-CRITERIA.md.

WhenQuestionIf the answer is no
End of M1Does the offline counter work reliably on real hardware?Fix before any supply-side work.
Pilot day 14Is the partner using it for every sale?Find the blocker; ship no new features.
Pilot day 30Would they pay, and would they refer someone?Re-interview; reconsider segment and pricing.
Before M4Is an APJ available to review the prescription workflow?Do not build v1.1 clinical features.
Before any "compliant / SIPNAP-ready" claimHas an APJ validated it against current official rules?Say "export" or "ledger", not "compliant".

MVP v1 "failed or needs rethink" if any of

  • Partner reverts to the old system or runs parallel records after day 30
  • Unexplained stock differences persist after two opname cycles
  • Any offline sale is lost or duplicated
  • A tenant-isolation or patient-data exposure occurs
  • Median sale time is slower than the partner's previous system

Phase 2 and Phase 3

Not scheduled. Ordered by dependency and expected value; re-prioritise from pilot evidence.

Phase 2 — Operations & control

  • Explainable defecta / reorder engine; supplier scorecard
  • Multi-branch: transfers with in-transit, branch comparison
  • Customer returns → quarantine → decision [VALIDATE]
  • Supplier returns; recall; destruction with witness [VALIDATE]
  • Controlled-medicine module: ledger, permissions, period reconciliation, export [VALIDATE]
  • Online order queue + prescription upload
  • SATUSEHAT connector + KFA sync [VALIDATE]
  • Mobile stock opname · promotions · membership · WhatsApp · accounting export

Phase 3 — Intelligence & ecosystem

  • Advanced forecasting; centralised procurement
  • Advanced multi-branch analytics; supplier recommendations
  • Marketplace / e-commerce connectors
  • AI analytics assistant: anomaly detection, invoice OCR, natural-language reports
  • Expanded clinical documentation; advanced loyalty and finance

AI sits after correct transactional data, and only as decision support. Never autonomous diagnosis, approval, or substitution.

What we are deliberately not doing

Never

  • Hospital EMR, appointments, laboratory system
  • Diagnostic AI or autonomous clinical decisions
  • Automated clinical substitution
  • Authoring interaction / dose / allergy logic from model knowledge

Not in v1 / v1.1

  • Full accounting ERP (we expose AP/AR + export)
  • Insurance / BPJS claims engine
  • Social-commerce marketplace
  • Heavy per-pharmacy configuration before the core is stable
